# 프로젝트: 주말축제 (Weekend Fest)

## 만들 것 (목적)
"이번 주말 뭐 하지?"에 답하는 모바일 원페이지 웹 서비스. 한국관광공사 TourAPI로 전국 축제를 사진 카드로 보여 준다.
타깃은 주말 나들이를 찾는 대학생·20대다. 상세 기획은 기획서를 따른다.

## 포함할 내용
- 축제 목록: 사진·축제명·기간·지역 카드, 12개씩 [더 보기]
- 기간 필터 [이번 주말]/[이번 달]/[다음 달] (기본: 이번 주말), 지역 필터 (전국 + 16개 시·도. 광주·전남은 실제 데이터가 전남광주통합특별시(12)로 와서 하나로 합침)
- 상세 시트: 카드를 누르면 아래에서 올라옴. 기간·주소·연락처·소개글·이용요금
- 진행 상태 뱃지: 진행 중 / 곧 종료(3일 이내) / D-n
- 찜하기: localStorage 저장, [찜한 축제] 탭
- 지도 링크: 카카오맵·네이버지도로 열기
- 로딩 스켈레톤, 결과 없음, 에러 + [다시 시도]

## 기술 스택
- React + Vite (JavaScript)
- 스타일은 Tailwind CSS v4만 사용 (`@tailwindcss/vite`)
- API: TourAPI `https://apis.data.go.kr/B551011/KorService2`
  (`searchFestival2`, `detailCommon2`, `detailIntro2`)
- 호출은 Vercel 서버리스 함수(`/api`)를 거친다. 인증키는 환경변수 `TOUR_API_KEY`

## 폴더 구조
- api/ : Vercel 서버리스 함수. 인증키는 여기서만 쓴다
- src/api : 프론트에서 /api 호출 + 응답 정규화
- src/components : 화면 단위 컴포넌트 (카드, 필터, 상세 시트 등)
- src/hooks : useFestivals(목록·필터·페이지), useLikes(찜)
- src/utils : 날짜 계산, 상태 뱃지, 지도 URL
- src/constants : 지역 코드표
- src/App.jsx : 컴포넌트를 조립만 한다

## 작업 방식
- 코드를 수정하기 전에 항상 계획부터 보여 준다. 계획에는 만들 파일 이름과 순서를 포함한다. 내가 승인하기 전에는 파일을 수정하지 않는다.
- 한 번에 하나의 기능만 구현한다. 한꺼번에 여러 개를 만들지 않는다.
- 애매한 부분은 구현 전에 질문한다. 추측해서 채우지 않는다.
- 작업이 끝나면 바뀐 파일 목록과 바꾼 이유를 설명한다.

## 규칙 (제약)
- 새 라이브러리를 설치하지 않는다 (라우터 포함). 필요하면 먼저 물어본다.
- 요청하지 않은 파일은 수정하지 않는다. 위 폴더 구조를 지킨다.
- 인증키를 코드에 쓰지 않는다. `VITE_` 변수로 만들지 않는다. `.env*`는 커밋하지 않고 `.env.example`만 커밋한다.
- 브라우저에서 TourAPI를 직접 호출하지 않는다. 항상 `/api`를 거친다.
- API 응답의 `items`가 빈 문자열이거나 객체 하나여도 항상 배열로 정규화한다.
- 사진이 없는 축제는 대체 화면을 보여 준다.
- 소개글은 `<br>`을 줄바꿈으로 바꿔 텍스트로 표시한다. `dangerouslySetInnerHTML`은 쓰지 않는다.
- 디자인: 배경 `stone-50`, 카드 흰색 `rounded-2xl`, 포인트 `orange-500`, 모바일 1열 / `sm` 이상 2열.

## 완료 조건
- npm run build가 통과한다.
- vercel dev로 화면과 /api가 정상 동작한다.
- 결과 0건·1건, 사진 없음에서도 화면이 깨지지 않는다.
- 찜이 새로고침 후에도 유지된다.
- 모바일 화면 너비(375px)에서도 레이아웃이 깨지지 않는다.
- Vercel 배포 링크에서 목록과 상세가 동작한다.
