# 숨쉬는 서울 — 프로젝트 기획서

> 서울 25개 구의 실시간 대기질을 보고, **지금 밖에서 뭘 해도 되는지** 바로 알려 주는 모바일 웹

## 1. 기획 과정 (AI와 질문을 주고받으며 결정)

강의 실습처럼 **[목적] [대상] [제약] [완료 조건]** 형식으로 첫 프롬프트를 쓰고, AI가 질문을 하나씩 던지면 고르는 방식으로 진행했다.

### 사용한 프롬프트 1 — 기획

```
[목적] Claude Code를 활용해 공공 API 기반의 웹 서비스를 기획하고 제작한다.
[대상] React 기초가 있고, 공공 API를 처음 실제 서비스에 붙여 보는 대학생 개발자(나).
[제약]
- 기술 스택은 React + Vite(JavaScript) + Tailwind CSS.
- 정부·지자체가 제공하는 공공 API를 사용한다.
- 인증키는 브라우저 코드에 넣지 않는다.
- Vercel에 배포할 수 있어야 한다.
- 처음부터 기획서나 코드를 쓰지 말고, 질문을 한 번에 하나씩 해서 단계적으로 정한다.
[완료 조건]
다음을 포함한 기획서를 완성한다.
- 활용할 공공 API / 서비스 컨셉 / 타깃 사용자 / 핵심 기능 / 화면 구성 / UI 방향 / 개발 범위
```

### AI 질문과 내 선택

| 단계 | AI 질문 | 내 선택 |
| --- | --- | --- |
| 1. 분야 | 어떤 공공 데이터에 관심이 있어? (교통 / 환경 / 문화행사 / 생활안전) | **환경 – 대기질** |
| 2. 범위 | 전국 vs 서울 | **서울** (구 단위로 내 동네를 바로 볼 수 있어서) |
| 3. 타깃 | 누가 주로 쓸까? | **산책·러닝 등 야외 활동을 하는 서울 시민** |
| 4. 핵심 가치 | 가장 먼저 얻고 싶은 정보는? | **“지금 나가도 돼?”에 대한 한 줄 답과 활동별 가이드** |
| 5. API | 서울시 실시간 대기환경 API / 에어코리아 API | **서울 열린데이터광장 `RealtimeCityAir`** (25개 구를 한 번에 줌) |
| 6. 키 관리 | 키를 어디에 둘까? | **Vercel 서버 함수에서만 사용** (`VITE_` 변수는 빌드에 그대로 들어가므로) |

## 2. 활용할 공공 API

- **서울시 권역별 실시간 대기환경 현황** — 서울 열린데이터광장 (data.seoul.go.kr)
- 요청: `http://openapi.seoul.go.kr:8088/{KEY}/json/RealtimeCityAir/1/25/`
- 응답 필드: `MSRSTN_NM`(구), `SAREA_NM`(권역), `PM`(미세먼지), `FPM`(초미세먼지), `OZON`(오존), `NTDX`(이산화질소), `CBMX`(일산화탄소), `SPDX`(아황산가스), `CAI_GRD`/`CAI_IDX`(통합대기환경 등급/지수), `CRST_SBSTN`(지수 결정 물질), `MSRMT_DT`(측정 시각)
- 주의할 점 (직접 호출해 보고 발견)
  - **http만 지원** → https인 Vercel 페이지에서 바로 부르면 Mixed Content로 막힌다 → 서버 함수로 중계
  - **sample 키는 최대 5건** → 키가 없으면 5개 구만 보여 주고, 화면에 안내
  - 에러는 JSON이 아닌 **XML**로 온다 → 서버 함수에서 메시지를 뽑아 JSON 에러로 바꾼다

## 3. 서비스 컨셉

미세먼지 앱은 많지만 대부분 **숫자**만 보여 준다. “PM2.5 28㎍/㎥”를 보고 러닝을 나가도 되는지 바로 판단하기는 어렵다.
**숨쉬는 서울**은 숫자를 **행동**으로 바꿔 준다 — 산책 / 운동 / 환기 / 마스크 네 가지를 등급별로 알려 준다.

## 4. 타깃 사용자

- 퇴근 후·주말에 한강 러닝, 산책을 하는 20~30대 서울 시민
- 아이·반려견 산책 전에 “오늘 괜찮나?”를 확인하고 싶은 사람

## 5. 핵심 기능

1. **우리 구 선택** — 25개 구 중 하나를 고르면 기억해 둔다 (다음 방문 때 바로 표시)
2. **한 줄 판정** — 통합대기환경 등급 + 미세먼지·초미세먼지 중 가장 나쁜 등급으로 “나가도 돼요 / 조심하세요” 표시
3. **활동 가이드** — 산책·운동·환기·마스크 4가지를 등급에 맞춰 안내
4. **오염물질 6종 상세** — 환경부 등급 기준으로 각각 좋음~매우나쁨 색 표시
5. **서울 전체 순위** — 지금 공기가 가장 좋은 구부터 정렬, 누르면 그 구로 이동
6. **새로고침 / 로딩 / 에러 처리** — 측정 시각 표시

## 6. 화면 구성 (한 페이지)

```
[헤더] 숨쉬는 서울 · 측정 시각 · 새로고침
[구 선택] 칩 버튼 25개 (가로 스크롤 없이 줄바꿈)
[판정 카드] 강남구 · 보통 · "가벼운 산책은 괜찮아요"
[활동 가이드] 산책 | 운동 | 환기 | 마스크
[오염물질] PM10 · PM2.5 · O3 · NO2 · CO · SO2
[서울 순위] 1. 도봉구 좋음 … 25. ○○구 나쁨
[푸터] 데이터 출처: 서울 열린데이터광장
```

## 7. UI 디자인 방향

- 등급 색은 국내 대기질 앱 관례를 따른다: 좋음 파랑 · 보통 초록 · 나쁨 주황 · 매우나쁨 빨강
- 판정 카드만 등급 색으로 크게, 나머지는 흰 카드로 차분하게
- 모바일 우선 (375px 기준), 데스크톱에서는 2열

## 8. 개발 범위와 구현 가이드

| 포함 | 제외 (이번 범위 아님) |
| --- | --- |
| 서울 25개 구 실시간 대기질 | 전국 데이터, 시간별 예보 |
| 등급·활동 가이드 (환경부 기준) | 로그인, 알림, 지도 |
| 선택한 구 기억 (localStorage) | 백엔드 DB |
| Vercel 서버 함수로 키 숨김 | 새 UI 라이브러리 |

구현 순서: 서버 함수 → 등급 유틸(+검사 스크립트) → 데이터 훅 → 컴포넌트 → 반응형 확인 → 배포

### 프롬프트 3 — Plan 모드 (Shift+Tab)
