# AI 활용 및 프롬프트 기록

이 문서는 **실제 대화에서 입력한 사용자 요청**과 **산출물 재현용 참고 프롬프트**를 구분합니다. 실행하지 않은 명령이나 입력하지 않은 프롬프트를 실제 사용 기록으로 표시하지 않습니다.

## 1. 실제 사용자 요청

### 사용자 메시지 (2026-11-22)
> 그럼 과제 2 여기서 진행해줘.

### 대화 맥락
앞선 대화에서 과제 자료를 검토했고, 과제 2의 예시 프로젝트로 '오늘의 하늘'(Open-Meteo 기반 국내 주요 도시 날씨 앱)이 제안되었다. 본 요청은 그 기획을 이어 실제 결과물을 생성해 달라는 의미다.

### AI가 수행한 작업
- 과제 PDF의 과제 2 세부 지시 확인
- Open-Meteo Forecast API 및 Vite 배포 공식 문서 검토
- 기획서·규칙 파일·구현 계획 정리
- React + Tailwind 기반 웹 프로젝트 작성
- 날씨 상태/옷차림/날짜/시간별 예보 유틸리티 테스트
- 테스트 결과와 실행 불가 항목을 구분해 기록
- 제출용 PDF 및 ZIP 패키지 생성

## 2. 재현용 프롬프트 (실제 채팅 입력 기록 아님)

다른 코딩 에이전트에서 동일한 작업을 재현할 때 사용할 수 있도록 프로젝트 생성 과정을 프롬프트로 정리했다.

### A. 기획
> React + Vite + Tailwind CSS로 국내 8개 도시의 현재 날씨, 12시간 예보, 7일 예보 및 체감온도 기반 옷차림을 안내하는 '오늘의 하늘' 웹을 기획해줘. Open-Meteo 공개 API를 사용하고 목적, 사용자 시나리오, 기능 요구사항, API 설계, 완료 기준을 `docs/PLAN.md`에 정리해줘. 구현은 아직 하지 마.

### B. 규칙 작성
> 기획서를 읽고 프로젝트 루트에 `AGENTS.md`를 작성해줘. 외부 API는 `src/api`, 상태 관리는 `src/hooks`, 유틸리티는 `src/utils`, UI는 `src/components`에 분리하고 새 라이브러리 설치 금지, 응답 오류 처리, 반응형, 보안 규칙을 포함해줘.

### C. 계획
> `AGENTS.md`를 읽고 코드는 변경하지 않은 채 파일별 구현 순서와 검증 방법을 계획해줘. 도시 선택부터 날씨 API, 현재 날씨/시간별/주간 예보, 옷차림 추천과 예외 처리까지 단계적으로 작성해줘.

### D. 구현
> 승인된 계획대로 React와 Tailwind CSS로 웹 서비스를 구현해줘. 민감정보는 저장하지 말고 Open-Meteo API에 브라우저에서 직접 요청해줘. 모바일 친화적인 카드 레이아웃, 재사용 컴포넌트, 네트워크 오류와 재시도 처리를 포함해줘.

### E. 검수 및 개선
> 코드 리뷰를 수행해줘. 빠른 도시 전환에서 이전 응답이 덮어쓰지 않는지, API 오류를 제대로 표시하는지, 날짜가 한국 시간 기준인지, 옷차림 추천이 강수 예보를 고려하는지 확인해줘. 발견된 문제는 개선하고 회귀를 막을 규칙을 `AGENTS.md`에 추가해줘. 테스트 및 빌드도 실행해 결과를 알려줘.

### F. 배포 준비
> Vercel 배포를 위해 `npm run build`, `.gitignore`, Open API 사용 권한 및 민감정보를 점검하고, GitHub PR 및 Vercel 연결 순서를 README에 작성해줘. 로그인/계정 권한이 필요한 작업은 사용자가 직접 하도록 명확히 안내해줘.

## 3. 주요 의사결정 기록
1. 서버 없이 동작하도록 공개 API를 채택했다.
2. 기상 데이터와 날씨 상태 해석을 분리했다.
3. UI 컴포넌트 재사용과 단위 테스트를 위해 유틸리티를 순수 함수로 설계했다.
4. API 오류 시 실시간 데이터처럼 보이는 임의 값을 제공하지 않는다.
5. API 및 npm 레지스트리 연결이 막힌 제작 환경에서 실제 외부 API/빌드 성공을 주장하지 않는다.
