> 공공데이터포털 국가자격 시험일정 API로 만드는 대학생용 자격증 일정 관리 웹 서비스
> 작성일: 2026-11-18 · 서비스 이름은 가칭이에요.

### 1-1. 실제 호출로 확인한 내용 (2026-11-18)

**요청 파라미터**

| 파라미터 | 필수 | 내용 |
|---|---|---|
| `implYy` | 예 | 시행년도 (예: `2026`). 빠지면 `resultCode 910`(필수 파라미터 누락)이 와요 |
| `numOfRows` | | 한 페이지 개수. **최대 50**이고, 넘으면 `resultCode 930`이 와요 |
| `pageNo` | | 페이지 번호 |
| `dataFormat` | | `json`으로 JSON 응답을 받아요. 프록시가 기본값으로 붙여요 |
| `qualgbCd` | | 자격구분: `T` 국가기술자격, `S` 국가전문자격, `C` 과정평가형, `W` 일학습병행 |
| `jmCd` | | 종목 코드. 없는 코드를 넣으면 0건이 와요. 넣으면 **그 종목이 속한 등급의 회차 일정**이 와요 (예: `1320` → 기사 일정 6건) |

**응답 구조:** `{ header: { resultCode, resultMsg }, body: { items: [...], numOfRows, pageNo, totalCount } }`. 정상이면 `resultCode`가 `"00"`이에요. **오류도 HTTP 200으로 와요.**

**item 필드:** 날짜는 모두 `YYYYMMDD` 문자열이고, 해당 일정이 없으면 빈 문자열이에요.

| 필드 | 뜻 |
|---|---|
| `implYy`, `implSeq` | 시행년도, 회차 |
| `qualgbCd`, `qualgbNm` | 자격구분 코드와 이름 |
| `description` | 예: `국가기술자격 기사 (2026년도 제3회)` |
| `docRegStartDt`, `docRegEndDt` | 필기 접수 시작·마감 |
| `docExamStartDt`, `docExamEndDt` | 필기 시험 시작·종료 |
| `docPassDt` | 필기 합격 발표 |
| `pracRegStartDt`, `pracRegEndDt` | 실기 접수 시작·마감 |
| `pracExamStartDt`, `pracExamEndDt` | 실기 시험 시작·종료 |
| `pracPassDt` | 실기(최종) 합격 발표 |

**설계에 영향을 주는 사실**

- **응답에 종목명이 없어요.** 일정은 종목별이 아니라 등급(기술사, 기능장, 기사, 기능사 등)과 회차별로 와요. 예를 들어 정보처리기사의 일정은 곧 "기사" 등급의 일정이에요. 따라서 종목 이름으로 검색하려면 **종목 목록(종목명 - 종목 코드 - 등급)을 따로 구해야 해요.** 후보는 [국가자격 종목 목록 정보](https://www.data.go.kr/data/15082998/fileData.do)(파일데이터, CSV·JSON 내려받기 가능)예요.
- **2026년 기사 일정은 6건이에요.** 3개 회차에 각각 두 건씩 있고, 같은 회차인데 필기 접수 기간만 달라요(예: 3회 `0720~0723`, `0801~0802`). 하나는 추가 접수로 보이지만, 응답만으로는 구분할 수 없어요.
- 2027년(`implYy=2027`) 일정은 아직 0건이에요. 지금은 연말이라 2026년의 남은 일정이 적으니, "곧 마감" 섹션이 비어 있을 수 있어요.
- 2026년 전체 일정은 157건이에요. 국가기술자격 74건 중 기능사가 58건이고, 국가전문자격은 75건이에요. 국가전문자격의 `description`(예: `전문자격 (2026년도 34회 면접)`)에도 종목명이 없어요.
- 호출 한도는 아직 확인하지 못했어요. 마이페이지의 활용신청 상세에서 확인해 주세요.
- **기능사는 같은 회차 번호에 시험일이 다른 일정이 여러 개 있어요.** 회차 번호도 1~41, 101~107, 201, 0처럼 여러 계열이에요. 그래서 회차를 묶을 때는 "필기 접수 기간을 뺀 모든 날짜가 같은 행"만 합쳐요. 2026년 기준으로 기사는 3개 회차, 기능사는 54개 회차예요.

### 1-2. 종목 목록 (검색용)

- **출처:** [국가자격 종목 목록 정보](https://www.data.go.kr/data/15082998/fileData.do) 파일데이터 `docs/한국산업인력공단_국가자격 종목 목록 정보_20251231.csv` (EUC-KR)
- **변환:** `npm run data:certs`를 실행하면 UTF-8 `src/data/certs.json`이 만들어져요. 613개예요(국가기술자격 513개, 국가전문자격 100개).
- **열:** 자격구분코드, 자격구분명, 계열명, 종목명. **종목 코드는 없어요.**
- **일정과 연결하는 방법:** 국가기술자격의 계열명(기술사, 기능장, 기사, 기능사)이 일정 API의 등급과 같아요. 산업기사는 "기사" 계열에 들어 있어요. 따라서 종목명 → 계열명 → `description`의 등급이 같은 일정으로 연결해요.
- **국가전문자격은 일정을 연결하지 않아요.** 일정 API의 `description`에 종목명이 없어서 어떤 자격증의 일정인지 알 수 없어요. 검색에는 나오지만 "일정 미제공"으로 표시해요.
- 상세 페이지 주소는 `/cert/종목명`이에요. 종목명은 중복이 없고, 변환 스크립트가 이를 검사해요.

## 2. 서비스 컨셉 및 주제

**"관심 자격증의 접수·시험·발표 일정을 D-day로 챙겨 주는 서비스"**

- 관심 자격증을 담아 두면 다음 일정까지 남은 날을 D-day와 월간 캘린더로 보여줘요. 다음 일정은 접수 시작, 접수 마감, 시험일, 발표일 중 가장 가까운 날이에요.
- "지금 접수 중"이거나 마감이 7일 이내로 남은 시험은 따로 모아 강조해요. 접수 기간을 놓치는 일을 막는 게 핵심 가치예요.

| 보조 타깃 | 스펙을 미리 쌓으려는 1~2학년 | 어떤 자격증을 딸지 둘러보는 중이에요 | 자격증 검색과 탐색, 1년 치 일정 확인 |

## 7. 개발 범위 및 구현 가이드

### 구조

```
브라우저 (React)  →  /api/exams (Vercel Function)  →  공공데이터포털 API
                       └ 서비스키는 환경변수 DATA_GO_KR_KEY에만 둬요
```

- **프록시를 두는 이유:** 브라우저에서 직접 호출할 때 생기는 CORS 오류를 피하고, 서비스키가 노출되지 않게 해요.
- **캐시:** 함수 응답에 `Cache-Control: s-maxage=86400`을 걸어 호출 한도를 아껴요.
- **로컬 개발:** `npm run dev`로 실행해요. Vite 플러그인이 `/api` 요청을 `api/*.js`로 연결해 줘서 Vercel CLI가 없어도 돼요.

### 라이브러리

- 추가: `react-router`, `lucide-react`(아이콘)
- 사용하지 않음: 달력 라이브러리(월간 그리드를 직접 만들어요), 날짜 라이브러리(기본 `Date`를 써요. 복잡해지면 `date-fns`를 검토해요)

### 일정 (4주)

| 주차 | 목표 | 완료 기준 |
|---|---|---|
| 1주 | `git init`, API 활용신청과 응답 확인, 프록시 함수, Vercel 첫 배포 | 배포 URL의 `/api/exams`에서 시험일정 JSON이 보여요 |
| 2주 | 라우터, 하단 탭바, 검색, 상세 | 자격증을 검색하면 상세 일정 표가 나와요 |
| 3주 | 관심 담기, 홈 D-day, 곧 마감 | 별 버튼으로 담으면 홈에 D-day가 보여요 |
| 4주 | 월간 캘린더, 반응형, 빈 상태·로딩·에러 처리 | 필수 기능 1~6을 갖춰 최종 배포해요 |
| 이후 | 선택 기능 7~10 | 하나씩 추가해요 |

### AI 코딩 도구 사용 방식

- 한 번에 기능 하나씩 요청하고, 브라우저에서 확인한 뒤 다음 기능으로 넘어가요.
- 실제 API 응답 구조를 확인하기 전에는 화면 코드를 만들지 않아요.
- 기능 하나가 끝날 때마다 `npm run lint`를 실행하고 커밋해요.

## 사용한 프롬프트

이번 과제에서 AI 코딩 도구(Claude Code)에 보낸 주요 프롬프트를 보낸 순서대로 정리했어요. 단계를 승인하는 짧은 답변은 어떤 질문에 답했는지 함께 적었어요.

### 1. 기획 시작 프롬프트

```
[목적] AI 코딩 도구를 활용해 공공데이터 API 기반의 웹 서비스를 기획하고 제작한다.

[대상] React 기초 지식이 있으며, AI 코딩 도구를 활용해 웹 개발을 경험하고자 하는 대학교 개발 동아리 학생.

[제약]
- 기술 스택은 React + Tailwind CSS를 사용한다.
- 공공데이터포털(data.go.kr) API를 활용한다.
- 프론트엔드 중심의 웹 서비스로 구현하고, Vercel에 배포한다.
- 처음부터 기획서나 코드를 작성하지 않고 단계적으로 진행한다.
- 질문은 한 번에 하나씩 제시하고, 답변을 바탕으로 다음 단계로 넘어간다.

[완료 조건]
최종적으로 다음 내용을 포함한 프로젝트 기획서를 완성한다.
- 활용할 공공 API 선정
- 서비스 컨셉 및 주제
- 주요 타깃 사용자
- 핵심 기능 목록
- 페이지별 화면 구성
- UI 디자인 방향
- 개발 범위 및 구현 가이드
```

### 2. CLAUDE.md 작성 요청

```
docs/기획서.md를 바탕으로 CLAUDE.md를 새로 써줘. 형식은 프로젝트 이름, 만들 것(목적), 포함할 내용, 기술 스택, 폴더 구조, 작업 방식, 규칙(제약), 완료 조건 순서로.
```

기획서가 아직 없어서, 기획을 먼저 이어서 하기로 했어요.

```
3번, 기획 이어서 할게. 질문 1부터 다시 해줘.
```

### 3. 기획 단계별 답변

| 순서 | 질문 | 보낸 답변 |
|---|---|---|
| 1 | 관심 분야 | `대학생활 분야` |
| 2 | 활용할 공공 API | `a, 자격증 시험` (국가자격 시험일정 API) |
| 3 | 서비스 컨셉 | `a+b 조합으로 할게` |
| 4 | 타깃 사용자 | `A 주 타깃, B 보조 타깃` (취업 준비 3~4학년 / 스펙 쌓는 1~2학년) |
| 5 | 핵심 기능 목록 | `좋아, 그대로 진행해줘` |
| 6 | 페이지별 화면 구성 | `좋아 이 구성으로 진행해줘` |
| 7 | UI 디자인 방향 | `a로 할게` (깔끔한 생산성 앱) |
| 8 | 개발 범위와 구현 가이드 | `지금 당장 끝나게 해줘` (제안 내용 확정, 기획서와 CLAUDE.md 작성) |

### 4. 개발 진행 요청

| 순서 | 프롬프트 | 내용 |
|---|---|---|
| 1 | `1주차 작업 시작해줘` | API 확인, 프록시 함수, git 초기 설정 |
| 2 | `키 넣었어, 2주차 작업 시작해줘` | 라우터, 하단 탭바, 검색, 상세 |
| 3 | `기획서에서 어떤 공공 API 쓰기로 했지?` | 사용할 API 다시 확인 |
| 4 | `키 다시 넣었어` | 서비스키 재설정 후 실제 응답 확인 |
| 5 | `a로 할게 파일 넣었어. docs 폴더에 있고, 인코딩이 EUC-KR이라 한글 깨지니까 UTF-8로 변환해서 써줘.` | 종목 목록 파일(국가자격 종목 목록 정보)로 검색 데이터 구성 |
| 6 | `3주차 작업 시작해줘` | 관심 담기, 홈 D-day, 곧 마감 |
| 7 | `4주차 진행해줘` | 월간 캘린더, 로딩·오류 처리, 반응형 마무리 |
| 8 | `선택 기능 진행해줘` | 등급별 둘러보기, .ics 내보내기, 공유 링크, 다크 모드 |
