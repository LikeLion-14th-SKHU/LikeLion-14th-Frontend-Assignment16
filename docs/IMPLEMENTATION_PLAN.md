# 승인된 구현 계획

1. React·Vite·Tailwind CSS 작업 환경을 구성한다.
2. `AGENTS.md`를 작성해 구조와 제약을 확정한다.
3. 도시별 좌표(`src/data/cities.js`)와 Open-Meteo 요청 코드(`src/api/weather.js`)를 작성한다.
4. WMO 날씨 코드와 옷차림 추천을 테스트 가능한 순수 함수로 분리한다.
5. `useWeather` 훅에서 로딩·오류·재시도·요청 취소를 구현한다.
6. 현재 날씨 히어로와 도시 선택 UI를 구성한다.
7. 상세 지표, 12시간 예보, 7일 예보 UI를 구현한다.
8. 반응형·접근성·상태 메시지를 보완한다.
9. 단위 테스트를 실행하고, 빌드·브라우저 검증을 진행한다.
10. 기획서·프롬프트 기록을 문서화하고 PR/Vercel 배포를 준비한다.

## 구현 중 결정
- 검색·지오코딩 대신 8개 도시의 검증 가능한 좌표를 고정해 외부 API 호출을 최소화한다.
- 화면의 날씨는 실제 API 응답으로만 표시하고, 오류가 나면 가짜 데이터 대신 복구 버튼을 보여준다.
- 추가 의존성을 만들지 않기 위해 SVG 아이콘과 Node 내장 테스트 러너를 활용한다.
- 사용자가 빠르게 도시를 바꾸면 이전 네트워크 요청을 중단한다.

## 검토 후 개선
- 처음에는 API 오류 메시지만 표시할 수도 있지만, 명확한 별도 오류 화면과 `다시 시도` 버튼이 필요하다.
- 응답 구조의 결손 가능성에 대비해 기본 형태를 검사한다.
- 시간별 예보는 현재 날짜·시각 이후의 항목만 보여준다.
- 주간 예보는 날짜별 강수확률과 기온을 함께 비교할 수 있도록 한다.
- 대응 규칙을 `AGENTS.md`에 추가해 다음 작업에서도 준수하도록 한다.
