# CLAUDE.md

## 프로젝트 제목

**한 칸 도트 공방** — 마인크래프트 양털로 그리는 도트 도안, 준비물표, 층별 쌓기 가이드

## 만들 것 (목적)

마인크래프트에서 양털로 픽셀아트(캐릭터, 벽화)를 짓기 전에 웹에서 도안을 그리거나 사진에서 만들어 보고, 필요한 양털 개수와 쌓는 순서를 바로 확인하는 한 페이지 웹 앱을 만든다.

- 한 칸 = 양털 블록 1개다. 도안을 칠하는 순간 준비물 수량이 정해진다.
- 대상 사용자는 캐릭터나 픽셀아트를 짓는 플레이어다. 서바이벌 모드에서 양털을 색별로 모아야 하는 사람, 양털 색을 아직 잘 모르는 입문자도 포함한다.
- mc-api는 단순히 그림을 가져오는 용도가 아니라 **실제 양털 텍스처·색, 제작법 그림, 게임 속 3D 렌더**처럼 이 앱의 핵심 기능에 쓴다. (사진 변환은 mc-api가 아니라 브라우저에서 직접 한다 — 아래 4번 참고)

## 포함할 내용

### 1. 도안 그리기
- 그림판 크기: **16 / 32 / 48 / 64** 중 도안을 만들 때 고른다(기본 32). 화면에서는 크게(데스크톱 약 800px) 보인다.
- 양털 **16색** 중 하나를 고르고 칸을 클릭하거나 **드래그**해서 칠한다. 빠르게 끌어도 칸이 빠지지 않게 직선으로 잇는다.
- **채우기** 도구: 같은 색으로 상하좌우 이어진 영역을 한 번에 칠한다.
- 지우개를 고르면 칸을 비운다(`null`).
- 우클릭(또는 Alt+클릭)은 스포이트: 그 칸의 색을 고른다.
- 마우스를 올린 칸에는 흰 테두리, 가로·세로 띠, 지금 고른 양털이 어떻게 찍힐지 미리보기(지우개는 빨간 표시)가 나온다. 빈칸은 칸마다 밝기를 번갈아 칠해서 칸이 또렷하게 보인다.
- 단축키: **B** 붓, **F** 채우기, **E** 지우개.
- 되돌리기: 버튼과 Ctrl/⌘+Z. 드래그 한 번 = 되돌리기 한 번. 최대 100단계.
- 눈금: 위쪽은 "왼쪽에서 몇 번째", 왼쪽은 "아래에서 몇 층". 16×16은 4칸마다, 그 이상은 8칸마다 굵은 안내선.

### 2. 준비물 세기 · 층별 쌓기 가이드
- 색별 양털 개수와 합계를 표로 보여 주고, 각 색을 서바이벌에서 구하는 법(양 털 깎기, 염료 조합)을 함께 적는다.
- 층별 가이드: 1층(맨 아래)부터 각 줄을 왼쪽 → 오른쪽 연속 구간으로 묶어 보여 준다(예: `빈칸 3 · 검은색×4 · 하얀색×2`). 줄을 누르면 그림판에서 그 줄만 또렷하게 보인다.
- 제작 체크리스트: 다 놓은 층을 체크하면 진행률(예: 3 / 18층)이 나오고 도안과 함께 저장된다. 그 층의 칸을 다시 칠하면 체크가 풀린다.
- 수량·가이드는 따로 저장하지 않고, 항상 `grid`에서 다시 계산한다(파생 값).
- 빈칸은 세지 않는다. 하얀 칸을 파란색으로 바꾸면 하얀색 −1, 파란색 +1이 된다.

### 3. 내 도안 (계속 저장해서 쓰기)
- 도안을 여러 개 만들어 보관한다. 그리는 대로 **자동 저장**된다(localStorage).
- 보관함에서 썸네일을 눌러 다른 도안을 열고, 이름 바꾸기·복제·삭제(확인 후)를 할 수 있다.
- 새 도안은 빈 도안(크기 선택) 또는 예시(펭귄 32×32, 크리퍼 얼굴 16×16, 하트 16×16)에서 시작한다. 지금 도안은 보관함에 그대로 남는다.
- 처음 실행하면 펭귄 예시 하나로 시작한다. 앱을 다시 열면 마지막에 보던 도안부터 이어서 그린다.
- 저장값이 깨졌으면 깨진 도안만 빼고 나머지를 살린다. 전부 깨졌으면 새로 시작한다. 예전 형식(`dot-studio:v1`) 도안은 보관함으로 옮겨 온다.

### 4. 사진으로 도안 만들기
- 사진(PNG/JPG/WebP)을 고르면 **브라우저 안에서 바로** 양털 도안으로 바꾸고, 옵션을 바꾸면 결과가 즉시 바뀐다. 사진은 어디로도 보내지 않는다.
- 옵션: 크기(16/32/48/64, 사진은 48 기본), 최대 색상(2~16, 많이 쓴 색만 남기고 나머지는 가장 비슷한 색으로), 맞춤 방식(가운데 잘라 채우기 / 전체 보이기), 선명하게(자동 밝기 보정 + 채도·대비), 디더링(규칙적인 격자무늬 Bayer).
- 방법(`woolConvert.js`): 절반씩 단계적으로 줄이기 → 밝기 분포 양 끝 2% 보정 → CIELAB 색 공간에서 가장 가까운 양털 고르기. 투명한 곳은 빈칸.
- **왜 mc-api 변환(`/v1/mapart`)을 쓰지 않나:** 그 변환은 게임 *지도* 색 기준이라 실제 양털 색과 다르다(예: 하늘색 지도색 `#6699d8` ↔ 하늘색 양털 `#3AAFD9`). 같은 사진으로 비교했을 때 색이 어긋나고 노란·초록 점이 흩뿌려졌다. 기준 색은 mc-api 텍스처에서 구한 실제 양털 색(`wools.js`의 대체 단색)이다.
- 원본과 변환 결과를 나란히 보여 주고, "새 도안으로 저장"을 눌러야 보관함에 들어간다.

### 5. 게임 속 3D 미리보기 (mc-api)
- 도안을 세워 놓은 양털 벽으로 보고 `POST /v1/render/3d/scene`로 렌더링한다. 각도: 정면 / 비스듬히 / 올려다보기.
- 크레딧이 드니까 **버튼을 눌렀을 때만** 호출하고, 예상 크레딧을 버튼에 표시한다. 도안이 바뀌면 "다시 렌더링" 안내를 띄운다.

### 5-1. 내보내기
- **도면 이미지(PNG)**: 칸마다 양털 번호가 적힌 도면 + 눈금(위: 몇 번째, 왼쪽: 아래에서 몇 층) + 범례(번호·이름·개수). 인쇄해서 보며 지을 수 있다.
- **명령어 파일(.mcfunction, Java)**: 기준점에서 오른쪽(동쪽)·위쪽으로 짓는 벽. 같은 색이 가로로 이어지면 `fill` 한 줄로 묶는다(펭귄 516칸 → 명령어 98줄). 파일 이름은 데이터팩 규칙(영문 소문자·숫자·`_`)에 맞춰 `dot_art_{N}x{N}.mcfunction`으로 고정.
- **준비물 목록 복사**: 이름과 개수를 글로 복사한다.

### 6. 양털 텍스처 · 제작법 (mc-api)
- 블록 목록에서 양털 16종의 텍스처를 찾아 그림판, 팔레트, 표에 같은 이미지를 쓴다.
- 이미지 로딩에 실패한 양털은 대체 단색으로 그려서 편집을 계속할 수 있게 한다.
- 팔레트에서 고른 양털의 제작대 조합법 그림을 `GET /v1/recipes/{id}/image.png`로 보여 준다(누를 때만).

#### API 정보 (2026-11-22 호출 확인)
- 기본 URL: `https://mc-api.bisai.dev`, 키 없이 사용. CORS `*`(POST 사전 요청 포함)라 브라우저에서 바로 호출한다.
- 크레딧: 응답 헤더 `x-credits-remaining`으로 남은 양을 알 수 있고, 화면 상단에 보여 준다.

| 용도 | 호출 | 비용 |
| --- | --- | --- |
| 블록 목록 | `GET /v1/assets/blocks` (약 1.3MB, 1,277개) — **앱 시작 시 1회** | 무료 |
| 텍스처 | `GET /v1/assets/textures/{icon}` (예: `block/white_wool.png`, 16×16 PNG) | — |
| 3D 렌더 | `POST /v1/render/3d/scene` 본문 `{ "query": "v=2&blocks=id.x.y.z*…&camera=yaw,pitch,0,dist&cameraTarget=x.y.z&projection=ortho&sky=day.0&width=720&height=720" }`. 16유닛 = 블록 1개, y가 위 | 2 + 블록 16개당 1 (최대 50) |
| 제작법 그림 | `GET /v1/recipes/{id}/image.png?recipe=<레시피 이름>` | 1 |

### 7. 화면 구성 (한 페이지)
- **상단 바:** 서비스 이름, 되돌리기, 사진으로 만들기, + 새 도안(강조색), 상태 문구, 남은 크레딧.
- **내 도안:** 썸네일 가로 목록 + 이름 바꾸기·복제·삭제.
- **왼쪽(넓게):** 그림판 → 층별 쌓기 가이드.
- **오른쪽(약 21rem):** 도구·양털 팔레트 → 준비물표 → 내보내기 → 3D 미리보기.
- **좁은 화면(`lg` 1024px 미만):** 상단 바 → 내 도안 → 그림판 → 팔레트 → 준비물표 → 내보내기 → 3D → 층별 가이드 순서로 세로 배치. 그림판은 화면 너비에 맞춘다.

### 8. UI 디자인
- 텍스처는 `image-rendering: pixelated` / `imageSmoothingEnabled = false`로 확대해도 흐려지지 않게 한다.
- 빈칸은 체크무늬로 표시해 하얀 양털과 구분한다.
- 선택한 색·도구에는 굵은 테두리(약 3px)와 한글 이름을 함께 보여 준다.
- 배경은 밝은 회색으로 하고, 강조색(초록)은 주요 버튼(+ 새 도안, 만들기, 저장)에만 쓴다. 나머지 색은 양털에서만 나오게 한다.
- 본문은 Pretendard, 제목만 픽셀 글꼴(Galmuri11).
- 접근성: 그림판(canvas)은 포커스를 받아 방향키로 칸을 옮기고 Enter/Space로 칠한다. 옮길 때마다 `"3행 5열, 파란색 양털"` 형태로 스크린리더에 읽어 준다. 색은 한글 이름으로도 구분할 수 있어야 한다. 대화상자는 `<dialog>`로 만들어 Esc로 닫힌다.

## 기술 스택

- **React** (Vite, JavaScript/JSX)
- **Tailwind CSS** (`@tailwindcss/vite` 플러그인)
- 상태 관리: React 내장 기능(`useState`, `useMemo`, `useEffect`, `useRef`)만 쓴다. 외부 상태 라이브러리는 쓰지 않는다.
- 그림판: `<canvas>` 1개 (최대 4,096칸이라 칸마다 버튼을 만들지 않는다)
- 저장소: 브라우저 `localStorage`
- 배포: **Vercel**

## 작업 방식

작업할 때 지킬 것:
- 한 번에 한 기능만 바꾸고, 바꾼 뒤에는 무엇이 달라졌는지 짧게 설명한다.
- 새 패키지를 설치해야 하면 먼저 이유를 말하고 확인을 받는다.
- 설명과 커밋 메시지는 한국어로 쓴다.
- 끝나면 `npm run build`와 `npx oxlint src`가 통과해야 한다.

## 규칙 (제약)

### 데이터 규칙
- 도안 `grid`는 **길이 size×size인 1차원 배열**이다. `index = row * size + col`. size는 16/32/48/64.
- 칸의 값은 양털 ID 문자열(예: `'blue_wool'`) 또는 빈칸 `null`만 허용한다.
- 준비물 수량과 층별 가이드는 state로 두지 않는다. `useMemo`로 `grid`에서 매번 계산한다.
- 칠하기는 불변 업데이트로 한다. 바뀌는 칸이 없으면 상태를 바꾸지 않는다(`applyCells`가 원래 배열을 그대로 돌려준다).
- 지우개는 `selected = null`로 처리해 같은 칠하기 함수를 쓴다.

### 저장 규칙
- localStorage 키: `dot-studio:v2`
- 저장 형식: `{ "version": 2, "currentId": "...", "designs": [{ "id", "name", "size", "cells", "updatedAt", "done" }] }`
  - `done`: 다 놓았다고 체크한 층 번호 배열(1 ~ size).
  - `cells`: 칸 하나를 글자 하나로 쓴 문자열. `'.'` = 빈칸, `'a'`~`'p'` = 양털(`wools.js` 순서). 64×64도 약 4KB.
- 복원할 때 `JSON.parse` 오류, 버전이 다른 경우, 글자 수가 size×size가 아닌 경우, 모르는 글자가 있는 경우를 걸러 낸다. 앱이 깨지면 안 된다.
- 보관함이 바뀌면 300ms 뒤 자동 저장한다. 저장에 실패하면 상단에 알린다.

### API 규칙
- 블록 목록은 앱 시작 시 **한 번만** 호출한다. 칠할 때마다 호출하지 않는다.
- 크레딧이 드는 호출(3D 렌더, 제작법 그림)은 **사용자가 버튼을 눌렀을 때만** 한다.
- API 키, 프록시 서버, 백엔드를 만들지 않는다.
- API가 실패해도 편집, 수량 계산, 저장은 대체 단색으로 계속 동작해야 한다. 실패하면 이유를 한국어로 보여 준다(429는 "잠시 후 다시").

### 범위 제한 (만들지 않는 것)
- 공유, 다른 형식 내보내기(.litematic, .schem), 로그인, 서버 저장
- 상자(64개) 단위 환산, 염료 개수 계산
- 이미 만든 도안의 크기 바꾸기
- TypeScript 전환, 외부 UI·상태 관리 라이브러리 추가

### 스타일 규칙
- 스타일은 Tailwind 유틸리티 클래스로 작성한다. 전역 CSS에는 `pixelated`, 체크무늬, 캔버스 색 변수 같은 공통 스타일만 둔다.
- 색상값을 컴포넌트 안에 직접 쓰지 않는다. 양털 색은 `wools.js`에서, 캔버스 선·체크무늬 색은 `index.css`의 `--canvas-*` 변수에서 가져온다.
