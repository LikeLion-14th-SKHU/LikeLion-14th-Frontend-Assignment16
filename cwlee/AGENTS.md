# Speedrun Stats — Frontend

Speedrun.com API를 활용하여 게임별 스피드런 기록을 분석하고, 세계 최고 기록의 변화와 사용자의 예상 순위를 확인할 수 있는 웹 서비스

## 프로젝트 목표
- 게임 검색 및 스피드런 카테고리 선택
- 세계 최고 기록 변화 그래프 제공
- 현재 세계 TOP 10 순위표 표시
- 사용자 기록 입력 및 예상 세계 순위 계산
- 별도 로그인 없이 이용 가능한 반응형 웹 서비스 구현

## 작업 범위
- 프론트엔드 중심으로 구현하며 별도 백엔드와 DB는 사용하지 않는다.
- Speedrun.com 공개 API를 사용한다.
- API 데이터를 가공하여 그래프와 순위표에 표시한다.
- 기획서에 없는 기능은 임의로 추가하지 않는다.

## 기술 스택
- Vite + React (JavaScript)
- Tailwind CSS v4
- React Router
- Recharts
- Fetch API
- Vercel

## 폴더 구조
- `src/api` — API 요청 함수
- `src/components` — 공통 UI 컴포넌트
- `src/pages` — 메인 및 기록 분석 페이지
- `src/hooks` — 재사용 가능한 커스텀 훅
- `src/utils` — 기록 시간 변환 및 순위 계산 함수
- `src/assets` — 이미지 등 정적 리소스

## API 및 데이터 규칙
- API 호출은 `src/api`에서 관리한다.
- API Base URL은 `https://www.speedrun.com/api/v1`을 사용한다.
- 게임과 카테고리는 API에서 제공하는 실제 데이터를 사용한다.
- 과거 검증 기록을 날짜순으로 정렬하여 최고 기록 변화 데이터를 생성한다.
- 예상 순위는 사용자보다 빠른 기록 수 + 1로 계산한다.
- 기록 시간은 내부적으로 초 단위로 처리하고 화면에서는 시·분·초 형식으로 표시한다.
- 기록이 없거나 API 요청에 실패한 경우 적절한 안내를 표시한다.
- 임의의 기록이나 순위를 실제 데이터처럼 표시하지 않는다.

## 코드 작성 규칙
- 함수형 컴포넌트와 React Hooks를 사용한다.
- 컴포넌트는 역할에 따라 분리하고 중복 코드를 최소화한다.
- 불필요한 state, useEffect, 추상화를 만들지 않는다.
- Tailwind CSS를 사용하며 별도의 CSS 작성은 최소화한다.
- 불필요한 라이브러리를 설치하지 않는다.
- 사용하지 않는 import, console.log, 주석 처리된 코드를 남기지 않는다.

## UI 규칙
- 미니멀한 게임 기록 분석 대시보드 스타일을 유지한다.
- 그래프와 기록 데이터의 가독성을 우선한다.
- 데스크톱과 모바일에서 사용할 수 있도록 반응형으로 구현한다.
- 로딩, 오류, 데이터 없음 상태를 구분하여 표시한다.
- 기존 디자인과 공통 컴포넌트를 최대한 재사용한다.

## 브랜치 · 커밋
- 커밋 메시지는 한국어로 작성한다.
- 커밋 유형은 `feat / fix / style / refactor / chore`를 사용한다.
- 기능 단위로 작업하고 변경 사항을 확인한 뒤 커밋한다.

## AI 작업 시 지킬 것
- 작업 시작 전 `AGENTS.md`를 확인한다.
- 구현 전에 변경할 파일과 작업 순서를 간단히 설명한다.
- 기존 파일 구조와 코딩 스타일을 유지한다.
- 요청하지 않은 기능이나 파일을 임의로 추가하지 않는다.
- 새로운 라이브러리 설치나 구조 변경이 필요하면 먼저 알린다.
- 변경한 파일과 주요 수정 내용을 요약한다.
- 완료 전 `npm run build`를 실행하고 오류가 없는지 확인한다.

- 현재 세계 TOP 10 순위표가 표시된다.
- 사용자 기록 입력 시 예상 순위가 계산된다.
